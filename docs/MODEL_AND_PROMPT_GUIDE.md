# Qwen3-1.7B 微调与角色提示指南

通用环境安装、数据选择、LoRA 参数、epoch 选择和训练监控请先看
[`REPRODUCTION.md`](REPRODUCTION.md)。本文只补充角色聊天场景中的数据和提示词设计。

## Qwen3-1.7B 是否适合

适合：

- 中文单角色语气模仿；
- 消费级显卡上的 LoRA 实验；
- 手机端量化部署和产品 Demo；
- 固定角色、短到中等长度对话；
- 与角色卡、世界书、记忆系统配合。

不适合单独承担：

- 复杂安全判断；
- 长上下文和长期记忆；
- 多角色世界观强约束；
- 高可靠知识问答；
- 需要稳定 JSON、工具调用或复杂推理的生产级任务。

本项目已经证明 1.7B 能在 RTX 4060 8 GB 上训练和推理，但证明的是工程可行性，
不是角色质量天然足够。

## 推荐微调步骤

1. 固定基座和版本；
2. 先测 Base + 角色提示，不急着训练；
3. 冻结数据，先做数据分布和近重复检查；
4. 训练第 1 轮，保存半轮和整轮；
5. 只有在明确改善时才继续到 1.5 或 2 轮；
6. 不默认训练 3 轮；
7. Base 与所有检查点使用同一提示词和生成参数；
8. 评测重复、长度、角色身份、事实边界、安全边界和多轮承接。

## 推荐训练参数

对 Qwen3-1.7B、小到中等规模单角色数据：

```yaml
finetuning_type: lora
lora_rank: 8
lora_alpha: 16
lora_dropout: 0.05
target_modules:
  - q_proj
  - k_proj
  - v_proj
  - o_proj
  - gate_proj
  - up_proj
  - down_proj
template: qwen3_nothink
cutoff_len: 512
per_device_train_batch_size: 1
gradient_accumulation_steps: 8
learning_rate: 5.0e-5
num_train_epochs: 1.5
lr_scheduler_type: cosine
warmup_ratio: 0.05
bf16: true
gradient_checkpointing: true
```

这只是安全起点。若数据只有数百个目标，应优先比较半轮、1 轮和 1.5 轮；
如果 rank 8 仍明显欠拟合，再尝试 rank 16。继续增大 rank 不能修复数据分布错误。

## 数据要怎么做

单角色数据不应只有一种问答长度或一种情绪。

推荐每个角色至少准备：

- 200 个普通校园或日常回复；
- 80–150 个情绪聆听和陪伴回复；
- 40–80 个不同意见、拒绝和边界回复；
- 40–80 个自然结束和话题切换回复；
- 40–80 个多轮承接回复；
- 10–20% 有自然动作或神态的回复；
- 10–15% 有自然追问的回复；
- 20% 左右较长回复，其余保持短句，形成可学习的长度差异。

每个目标应来自不同上下文，避免用同一条回复填充多个场景。

## 角色提示词写多长

建议使用三层：

| 层级 | 中文字符 | Qwen3 Token | 适用场景 |
|---|---:|---:|---|
| 极简身份 | 10–40 | 7–30 | 模型已经通过 LoRA 学会角色 |
| 核心人格 | 100–250 | 70–180 | 推荐默认 |
| 完整角色卡 | 350–800 | 250–600 | 复杂世界观或强身份约束 |

本项目 Xu Cheng 的完整卡约 1,225 Token，明显过长；它增加规则，但压缩了可用于生成回答的
注意力预算。经验上，小模型使用 70–250 Token 的核心提示更平衡。

## 核心提示模板

```text
【身份】
你是〈姓名〉，〈年龄/身份〉。用户是〈关系〉。

【性格】
〈3–5 个核心特征；同时写清不能出现的行为〉

【关系与称呼】
你称用户为〈称呼〉，自称〈称呼〉。当前关系是〈阶段〉，不要自行升级。

【说话方式】
先回应用户当前内容；普通回复 1–3 个短段，复杂话题再展开。
可以少量使用动作或神态，单条最多一个。

【事实边界】
不知道就承认；不编造共同经历、用户现实信息或专业知识。

【禁止】
不要自称 AI；不要每轮请安；不要用固定句子反复追问；不要逐条复述设定。
```

不要让提示词替模型写完整答案，也不要堆叠几十条互相冲突的规则。
最好用少量“行为原则 + 一个简短风格示例”表达。

## 为什么不是训练越久越好

小数据 LoRA 首先学习训练集的高频分布。继续训练通常会：

- 强化固定句式和口头禅；
- 降低回答长度；
- 扩大训练集与真实用户分布之间的偏差；
- 使安全边界和普通能力进一步漂移。

本项目五个角色案例的最佳体验点分别出现在半轮、1 轮和 1.5 轮附近，没有证据支持统一
训练 3 轮。

## 交付标准

要声称 LoRA 有效，至少需要：

- 未参与训练和选模的最终问题；
- 同一 Base 与 LoRA 参数；
- 自动格式诊断；
- 人工或独立评委的 A/B 对比；
- 对角色、自然度、连贯性、重复、安全、事实和通用能力分别报告；
- 保留失败样本和不利结果。
