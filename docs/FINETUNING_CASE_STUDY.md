# 为什么微调结果会变成这样

本文总结 RoleBench 孙悟空、许澄和宋知意三个 LoRA 实验中的共同规律。

## 现象

三个实验都出现了类似现象：

1. 训练 loss 持续下降；
2. LoRA 学会了角色称谓或句式；
3. 回答也经常变得比 Base 更短；
4. 某些检查点开始复读固定短语；
5. 继续训练后，回答自然度、信息量和安全性并不一定同步提升。

结论：**loss 衡量的是对训练目标 Token 的预测能力，不衡量真实聊天质量。**

## 案例一：悟空 RoleBench

数据：

- 1,260 条训练样本；
- 146 条验证样本；
- 2 epoch，316 步；
- 最终验证 loss `1.9276`。

结果：

- Base 输出 Token 中位数约 82.5；
- 最终 LoRA 约 34.5；
- 作者 30 对盲评中 Base 更好 27 次、LoRA 更好 0 次、平局 3 次；
- LoRA 学会了“俺老孙”等身份称呼，但丢失了 Base 通过角色卡表现出的动作和叙事感；
- 从最早的 70 步检查点就已经明显变短，说明问题来自训练分布，而不是只有最后几轮过拟合。

原因：

- RoleBench 大量样本是角色口吻的短问答和任务回答；
- 训练集只有约 3.5% 样本包含动作；
- 模型优先学习高频的“短答案 + 身份词”模式；
- Base 在完整角色卡下本来已经能表现角色，LoRA 反而覆盖了更强的语言能力。

## 案例二：许澄

数据：

- 80 段训练多轮对话；
- 20 段验证多轮对话；
- 展开后为 576 个训练 assistant 目标和 142 个验证目标；
- 2 epoch，144 步；
- 验证 loss `6.0052 → 2.9014`。

结果：

- 自动开发集因安全失败次数最少，选择第一轮半程；
- 作者实际对话后更偏好完整第一轮配合核心提示；
- 最终测试仍出现阻止用户结束聊天、保存密码、提供欺骗建议、角色经历编造和过度简短。

主要原因：

- 训练提示很长，而实际测试曾使用明显更短的核心提示，存在提示分布变化；
- 教师模型生成的对话覆盖面有限，礼貌、温柔和安全的表层句式过多；
- 低风险日常很多，但困难边界、危机、拒绝和说话人归属样本仍不足；
- 训练目标是“像许澄”，未单独优化“不要重复”“凭证必须拒绝”等硬规则；
- 安全评价和自然度评价由不同流程完成，二者的最优 checkpoint 不一致。

## 案例三：宋知意

数据：

- 64 段训练、8 段验证、8 段测试；
- 展开后为 276 / 35 / 35 个 assistant 目标；
- 2 epoch，共 70 步；
- 验证 loss `6.3685 → 3.6651`。

结果：

- 自动开发评分较高的候选是 1.5 轮，但曾有一次硬失败；
- 按“零硬失败”规则选择第一轮半程；
- 作者直接对话后最偏好 1.5 轮 + 训练同款精简提示；
- 完整角色卡或较晚训练轮数并没有稳定优于精简提示。

主要原因：

- 训练使用精简提示，推理沿用同样提示时分布更一致；
- 276 个目标只能让模型学会较短的角色表达习惯，不能支撑大规模风格搜索；
- 训练数据规模小，验证 loss 的细小改善很容易被采样随机性和表达长度影响；
- “安全门禁最优”“自动评分最优”“作者主观体验最优”不是同一个目标。

## 共同根因

### 1. 数据分布直接决定输出长度

教师模型生成的目标大多在 30–50 个汉字。LoRA 会学习这种长度和结构，
即使用户要求详细回答，也可能继续输出短句。

### 2. 高频模式会被放大

短语、敬语、动作、安慰模板和固定结尾出现得越多，LoRA 越容易把它们当作默认行为。
“不要重复”是抽象规则，训练中的实际 Token 分布影响更强。

### 3. 模型会把上下文中的错误继续放大

自由对话评测保留模型刚生成的回答。如果某轮生成固定句子，下一轮历史会再次强化该模式，
于是自动评测看起来像“突然开始复读”。

### 4. 训练提示和推理提示必须一致

训练使用完整角色档案、推理只给一句提示，或反过来，都会改变条件分布。
宋知意最稳定的结果来自训练和推理使用同一版精简提示。

### 5. 小数据的 loss 不能用于选最终产品

验证 loss 下降可能只表示模型更会复制目标的平均长度、句式和常见短语。
角色一致性、自然度、边界、重复和事实正确性必须分别评测。

### 6. 选模标准会改变最佳权重

- 许澄自动流程优先安全零失败，最终选择半轮；
- 宋知意自动流程也优先零硬失败，选择第一轮半程；
- 作者自由聊天更重视自然感，分别偏好许澄第一轮和宋知意 1.5 轮。

这些结果并不矛盾，而是不同评测目标的取舍。

## 可复现的改进方向

1. 训练和推理严格使用同一提示版本；
2. 先检查目标长度分布，避免全是很短的回复；
3. 增加动作、情绪、拒绝、边界、自然结束和多轮修复样本；
4. 固定同一批问题，同时比较 Base 和半轮、1 轮、1.5 轮、2 轮；
5. 分别统计重复、极短回答、角色称谓、事实冲突、安全边界和任务完成；
6. 小数据训练通常先在 1 轮或 1.5 轮停止，不把 3 轮作为默认；
7. 最终发布前使用未参与调参的留出集和人工盲评。
