# 五个角色 LoRA 实验的结果与失败模式

本文放在复现指南之后阅读。先按 [`REPRODUCTION.md`](REPRODUCTION.md) 跑通数据、标签和
训练流程，再判断这些结果是否适用于自己的数据。

## 总表

| 实验 | 数据来源 | 数据规模 | 训练 | 主要结果 |
|---|---|---:|---|---|
| 孙悟空 | RoleBench 衍生数据 | 1,260 训练 / 146 验证 | 2 轮，316 步 | 学会角色称谓，但回答明显变短；数据与权重不公开 |
| 许澄 | 原创教师生成数据 | 576 / 142 目标 | 2 轮，144 步 | 作者偏好第 1 轮 + 核心提示；仍有安全与长度问题 |
| 宋知意 | 原创教师生成数据 | 276 / 35 / 35 目标 | 2 轮，70 步 | 作者偏好第 1.5 轮 + 训练同款精简提示 |
| 凉宫春日 | ChatHaruhi 固定子集 | 1,009 / 115 | 2 轮，254 步 | 角色口吻出现，但动作与叙事表达下降；许可冲突，不发布 |
| 裴既明 | 原创乙女向数据 | 577 / 54 / 45 目标 | 2 轮，146 步 | 开发集选中第 1 轮；角色相关指标改善，但仍比 Base 短 |

结论不是“训练越久越好”，而是：**LoRA 很快学会角色称谓、长度和句式分布；数据分布、
提示一致性和检查点选择往往比继续增加 epoch 更重要。**

## 孙悟空：角色词学会了，叙事感丢了

数据为 RoleBench 中的角色问答及项目补充样本。最终验证 loss `1.9276`。

- Base 输出 Token 中位数约 82.5；
- 最终 LoRA 约 34.5；
- 作者 30 对体验比较中 Base 更好 27 次、LoRA 0 次、平局 3 次；
- LoRA 学会“俺老孙”等角色词，但动作和叙事感低于完整角色卡下的 Base；
- 从较早检查点开始就出现长度收缩，说明主要问题来自训练分布。

数据中动作回复比例很低，而短问答比例高。模型优先学到“短句 + 角色称谓”，没有学会
完整角色卡本来能激发的长动作描写。第三方衍生边界不允许公开数据或 Adapter。

## 许澄：不同目标选出不同检查点

原创角色，80 段训练、20 段验证，展开为 576 / 142 个 assistant 目标。2 轮共 144 步，
验证 loss `6.0052 → 2.9014`。

- 自动安全门禁选择第 1 轮半程；
- 作者实际对话更偏好完整第 1 轮 + 核心提示；
- 封存测试仍发现阻止结束聊天、保存密码、提供欺骗建议、角色经历编造和过度简短；
- 训练使用较长提示，实际测试曾使用短核心提示，存在条件分布变化；
- 教师生成数据中礼貌、温柔和安全的表层句式较多，困难边界样本不足。

这是仓库中一个可完整复现的案例：数据和 Adapter 都包含。可复现的是流程与已知问题，
不是“安全质量已经通过”。

## 宋知意：训练与部署提示一致更重要

原创校园角色，64/8/8 段数据，展开为 276/35/35 个目标。2 轮共 70 步，验证 loss
`6.3685 → 3.6651`。

- 自动开发集曾偏好 1.5 轮，但出现一次硬失败；
- 按零硬失败规则曾选择 1 轮半程；
- 作者直接体验更偏好 1.5 轮 + 训练同款精简提示；
- 完整角色卡没有稳定优于精简提示；
- 276 个目标只够学习较小范围的角色表达，不能支撑大规模风格搜索。

这个案例说明“开发评分最优”“安全门禁最优”和“作者实际聊天偏好”不是同一个目标。

## 凉宫春日：54K 聚合不等于 54K 目标角色

ChatHaruhi 54K 中只有 1,163 行以目标角色为 assistant；清洗后为 1,009 训练、115 验证
和 24 条独立题目。2 轮 254 步，最终验证 loss `2.0476`。

- 完整角色卡下，Base 在 24 个检查点中有 19 次括号动作表达；
- 四个 LoRA 检查点均为 0/24；
- 输出 Token 从 Base 约 72–83 缩短到 LoRA 约 35–41；
- 部分边界题出现替代利益交换或规避式回答，Base 也并非全部通过；
- 作者后续更偏好 1.5 轮 + 完整角色卡，但这不能撤销动作退化和边界失败。

数据卡与项目 README 的许可说明冲突，底层作品另有权利约束。因此仅保留本地非商业研究
记录，不公开数据、Adapter 或量化权重。

## 裴既明：降低容量缓解，但没有根治短回答

原创乙女向角色，96/13/11 个场景，展开为 577/54/45 个目标，并有 60 个长回复训练分支。

第一轮配方使用 rank 8 和七个投影层，2 轮 146 步。验证 loss `6.8656 → 3.3835`，但
开发集平均字符数从 Base 58.2 降到半轮 14.2、第 1 轮 28.2。

最终采用：

- rank 4、alpha 8；
- 只训练 q/k/v/o；
- LR `2e-5`；
- 60 字以上目标权重 3.0；
- 保存半轮、整轮、1.5 轮和 2 轮。

开发集自动审查中第 1 轮为 0 个硬失败，因此进入封存测试。封存结果：

| 维度 | Base | 第 1 轮 LoRA |
|---|---:|---:|
| Persona | 1.182 | **1.545** |
| Context | 1.091 | **1.364** |
| Naturalness | 1.455 | **2.182** |
| Length fit | 1.909 | **2.455** |
| Overall | 1.182 | **1.545** |
| 硬失败 | 2 | **1** |

LoRA 平均回复 40.2 字，Base 为 58.4 字。角色相关指标提高，但长度回归仍存在。评审来自
单一 LLM 裁判，不是多人人工盲评。

## 共同根因

### 1. 目标长度会直接变成模型习惯

短目标占主导时，模型会把简短当作默认行为，即使提示词要求详细回答。

### 2. 高频句式会被放大

称谓、敬语、安慰模板、动作和固定结尾出现越多，LoRA 越容易把它们变成默认模式。

### 3. 提示分布必须一致

训练用完整角色卡、推理用短提示，或反过来，都会改变模型看到的条件。最稳定的结果通常
来自训练和部署使用同一个提示版本。

### 4. loss 不衡量角色质量

验证 loss 下降可能只是模型更会复制目标的平均长度、句式和常见短语。角色一致性、自然度、
事实、边界和重复需要单独评测。

### 5. 不同目标会选不同检查点

安全门禁、自动评分和人的自然聊天偏好不一定选择同一个 epoch。发布时必须说明按什么目标
选择了权重。

## 可执行的改进顺序

1. 先测 Base + 正式提示；
2. 审计目标长度、动作、问句、结束和边界分布；
3. 按会话划分 train/validation/test；
4. 只监督最终 assistant 回答和 EOS；
5. 先训练半轮和一轮；
6. 用固定问题和真实聊天比较 Base、0.5、1、1.5、2 轮；
7. 出现复读或长度坍塌后停止增加 epoch；
8. 检查点只用开发集选择，封存测试只运行一次；
9. 保留失败结果，不用更漂亮的截图替代它们。
